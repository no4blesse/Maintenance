# คู่มือใช้งานย่อ

## ผู้ดูแลระบบ

1. ตั้งค่าโรงแรม → อาคาร → ชั้น → ห้อง/พื้นที่ และแผนก
2. สร้างผู้ใช้ กำหนดบทบาทแยกรายโรงแรม ตั้งอัตราค่าแรงช่างตามวันที่มีผล
3. ตรวจ SLA ราย priority/โรงแรม กฎนี้ใช้กับใบงานใหม่
4. เพิ่มประเภทอุปกรณ์/แค็ตตาล็อกอะไหล่จากบัญชีระดับกลุ่ม
5. ตั้งค่า LINE และ cron ตามคู่มือแยก

รหัสผ่านใหม่อย่างน้อย 10 ตัว มีตัวพิมพ์ใหญ่ ตัวพิมพ์เล็กและตัวเลข บัญชีที่ผู้ดูแลสร้างหรือ reset จะถูกส่งไปหน้าโปรไฟล์ให้เปลี่ยนรหัสผ่านก่อนใช้โมดูลอื่น

## แจ้งซ่อม → ตรวจรับ

ผู้แจ้งเลือกโรงแรม ระบุสถานที่/อุปกรณ์ หมวดงาน ความเร่งด่วนและอาการ แนบรูป แล้วบันทึก ระบบสร้างเลขที่แยกโรงแรม/ปีและประวัติอัตโนมัติ

ช่างเปิดใบงานใหม่ของโรงแรม → กด “รับเรื่องและเริ่มงาน” → ระบบใช้บัญชีช่างผู้กดเป็นผู้รับงาน พร้อมเวลาเริ่มจากเซิร์ฟเวอร์และเปลี่ยนเป็นกำลังดำเนินการทันที → บันทึกเวลาทำงานที่ใช้คิดค่าแรงและรายละเอียดงาน → เบิกอะไหล่จากหน้าใบงาน → แนบภาพหลังซ่อม → แจ้งซ่อมเสร็จพร้อมบันทึก ผู้ตรวจรับคนละคนตรวจงานและปิดงาน

รออะไหล่/ผู้รับเหมา/อนุมัติ ใช้ปุ่มตามสถานะปัจจุบัน ปุ่มที่ไม่มีสิทธิ์ไม่แสดงและ server ตรวจซ้ำเสมอ การยกเลิก/reopen/reject ต้องมีเหตุผล คำขออนุมัติการทำงานใช้ฟอร์มคำขอในหน้ารายละเอียด ส่วนการตรวจรับงานเสร็จใช้ปุ่ม workflow “ตรวจรับและปิดงาน”

## คลังอะไหล่

ยอดแยกตามโรงแรมและ moving weighted-average cost รับเข้า/เบิกทั่วไป/คืน/ตรวจนับ ใช้ฟอร์มในหน้าคลัง ต้องระบุเหตุผล การใช้วัสดุในงานซ่อมให้เบิกจากใบงานเพื่อเชื่อมต้นทุน การคืนวัสดุที่เบิกผิดจากใบงานจะสร้าง reversal และ void cost เดิม

การตั้ง threshold/bin ทำจากรายการอะไหล่ → รายละเอียด → ตั้งค่าสต็อก คำขอโอนเลือกต้นทาง ปลายทาง อะไหล่ จำนวน ผู้มีสิทธิ์ต้นทางอนุมัติ (ตัดสต็อกเป็น IN_TRANSIT) และปลายทางกดรับจึงเพิ่มยอดปลายทาง ผู้ขออนุมัติตนเองไม่ได้

คำขอซื้อแยกขั้นขอ → อนุมัติ → รับเข้า รับซ้ำไม่ได้ การซื้อเข้าไม่เป็นค่าใช้จ่ายบำรุงรักษาจนกว่าจะเบิกใช้กับงาน

หน้าขอโอน/ขอซื้อปัจจุบันรับหนึ่งรายการต่อเอกสาร Service รองรับโอนหลายรายการ แต่ยังไม่มีตัวแก้หลายบรรทัดใน UI

## อุปกรณ์และ PM

เพิ่มอุปกรณ์โดยเลือกโรงแรมก่อน ระบบโหลดห้อง/แผนกตามโรงแรม จากนั้นเลือกประเภท ชื่อ serial วันที่ซื้อ ประกัน สภาพ และเอกสาร รูป/คู่มือเก็บ private

ป้าย QR เปิดหน้ารายละเอียดหลัง login และตรวจสิทธิ์ ผู้ใช้ที่ไม่มีสิทธิ์โรงแรมของอุปกรณ์เปิดไม่ได้

แผน PM ระบุวันเริ่ม ความถี่ ผู้รับผิดชอบ และ checklist หนึ่งรายการต่อบรรทัด เช่น:

```text
ตรวจแผ่นกรอง | CHECK
แรงดันน้ำ | NUMBER | bar
ข้อสังเกต | TEXT
```

Cron สร้างใบงานตามรอบ กดสร้างงานตามรอบที่ถึงกำหนดได้ด้วยสิทธิ์ pm.manage การรันซ้ำไม่สร้างรอบเดิมซ้ำ Checklist ถูก snapshot ต่อใบงาน ช่างต้องตรวจครบและใส่ค่ารายการ NUMBER/TEXT ก่อนแจ้งเสร็จ พบปัญหาระหว่าง PM สร้างใบแจ้งซ่อม corrective จากหน้าใบงานเดียวกันได้

## รายงานและต้นทุน

เลือกโรงแรมและช่วงวันที่ใน Dashboard/KPI/รายงานต้นทุน CSV มี UTF-8 BOM และป้องกัน spreadsheet formula injection รายงานพิมพ์ใช้ปุ่มพิมพ์/Save as PDF ของ browser

ต้นทุนอะไหล่/ค่าแรงเกิดอัตโนมัติจากใบงาน ส่วนผู้รับเหมา/เปลี่ยนอุปกรณ์/อื่น ๆ บันทึกในเมนูต้นทุนและรอผู้อนุมัติคนอื่น งบประมาณดู variance และ utilization แยกโรงแรม/ช่วง/ประเภท

## ขอบเขตและข้อมูลสาธิต

บางรายการ cap จำนวนแถวเพื่อคุมหน่วยความจำ ให้แบ่งโรงแรมหรือช่วงเวลาเมื่อมีข้อมูลมาก ภาษาอังกฤษยังมี Thai fallback ในข้อความใหม่บางส่วน DEMO เป็นข้อมูลทดสอบในฐานทดสอบเท่านั้น ห้ามนำยอด DEMO ไปใช้รายงานปฏิบัติงานจริง


เวลาซ่อมเสร็จบันทึกอัตโนมัติเมื่อกด “แจ้งซ่อมเสร็จ” และไม่เปลี่ยนตามเวลาที่ผู้จัดการตรวจรับ เวลาตรวจรับ/ปิดงานเป็นอีกช่องหนึ่ง หากไม่ผ่านตรวจรับจะล้างเวลาซ่อมเสร็จเพื่อให้ทำงานต่อได้ เปิดงานใหม่จะเริ่มรอบเวลาใหม่เมื่อช่างคนเดิมรับอีกครั้ง โดยเก็บประวัติเดิมใน audit/status/assignment logs งานที่เริ่มแล้วไม่สามารถลากเปลี่ยนเวลาในปฏิทินได้ การคิดค่าแรงยังใช้ work log ที่บันทึก ไม่ใช้เวลารอทั้งหมดมาคิดค่าแรงอัตโนมัติ
