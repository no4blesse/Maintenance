# หน้าแจ้งซ่อมสำหรับผู้ไม่มีบัญชี

เปิดลิงก์เฉพาะโรงแรม `/repair/NT`, `/repair/CC`, `/repair/LS` หรือ `/repair/SG` ได้ทั้งลูกค้า พนักงาน และผู้ใช้ที่ลงชื่อเข้าใช้อยู่ ไม่มีการสร้างบัญชีหรือให้สิทธิ์หลังบ้าน หน้าเข้าสู่ระบบและหน้าเพิ่มใบงานหลังบ้านมีลิงก์ไปยังแบบฟอร์มนี้

ขั้นตอน: เปิดลิงก์ของโรงแรมและดูชื่อโรงแรมที่แสดง → ระบุประเภทและชื่อผู้แจ้ง → ระบุห้อง / จุดที่เสีย → ประเภทปัญหา หัวข้อและรายละเอียด → แนบรูปถ้ามี → ส่งและเก็บเลขที่ใบงาน ติดต่อแผนกต้อนรับด้วยเลขนี้เมื่อต้องการสอบถาม

ลิงก์เฉพาะโรงแรมแสดงชื่อไทย อังกฤษ และรหัสโรงแรมชัดเจน ไม่มี dropdown หรือตัวเลือกสลับโรงแรม โรงแรมผู้รับถูกกำหนดจาก URL ฝั่งเซิร์ฟเวอร์ ไม่รับ hotel_id จาก form หรือ query แม้ดัดแปลงค่าก็ไม่ส่งงานข้ามโรงแรม ใช้ nonce และใบรับแจ้งแยกตามโรงแรมเพื่อเปิดหลายแท็บได้อย่างอิสระ ปุ่มแจ้งเพิ่มและโลโก้กลับมาที่โรงแรมเดิม

หน้า `/repair` เป็นสารบัญลิงก์สำหรับเจ้าหน้าที่ ไม่มีแบบฟอร์มส่งงานรวม ควรนำลิงก์เฉพาะโรงแรมไปแชร์หรือทำ QR ให้ลูกค้า ลิงก์เดิมแบบ `/repair?hotel_id=1` จะ redirect ไป URL ของโรงแรมนั้น ส่วน POST ไป `/repair` ไม่รับสร้างใบงานอีกแล้ว โรงแรมไม่ถูกต้องหรือปิดใช้งานตอบ 404 ไม่มีรายการอุปกรณ์ รายชื่อบุคลากร หรือข้อมูลหลังบ้านในหน้าแบบฟอร์ม

เมื่อส่งสำเร็จ ระบบสร้าง tickets สถานะ NEW ความเร่งด่วน NORMAL และแจ้งทีมดูแลด้วยระบบแจ้งเตือนเดิม หัวหน้าช่างตรวจข้อมูลและปรับความเร่งด่วนได้ ช่างผู้มีสิทธิ์ของโรงแรมกดรับเรื่องด้วยบัญชีตนเองเพื่อเริ่มงานและบันทึกเวลาอัตโนมัติ ชื่อผู้แจ้งเป็นข้อมูลที่ผู้กรอกระบุ ไม่ใช่ผู้ใช้ที่ผ่านการยืนยันตัวตน แม้เปิดแบบฟอร์มจาก session ที่ล็อกอินอยู่ก็ไม่ผูกใบงานกับบัญชีนั้น

ช่องทางติดต่อเป็นตัวเลือก เก็บใน `public_repair_submissions` ผู้ปฏิบัติงานที่มีสิทธิ์ดูใบงานของโรงแรมนั้นจะเห็นบนหน้ารายละเอียดใบงาน รูปอยู่ใน private storage ใช้การตรวจชนิดจากเนื้อไฟล์ จำกัด JPG / PNG / WebP สูงสุด 3 รูป ขนาดต่อรูปไม่เกินค่าที่เล็กที่สุดระหว่าง 5 MB, upload_max_mb และ PHP upload_max_filesize

หน้ารับแจ้งสำเร็จแสดงเพียงเลขอ้างอิงและโรงแรมของการแจ้งล่าสุดของโรงแรมนั้นใน session นี้ ไม่มี endpoint สาธารณะให้ค้นใบงานจากหมายเลข ID หรือเลขที่ใบงาน การติดตามออนไลน์แบบไม่ล็อกอินยังไม่ได้เปิดใช้งาน

การส่งใช้ CSRF, nonce ที่ผูกกับ session, honeypot และจำกัด 10 ใบต่อ IP ต่อชั่วโมง นับผ่านฐานข้อมูลและ lock ป้องกันคำขอพร้อมกัน เก็บ IP เป็น HMAC ในตาราง intake; audit log เดิมยังบันทึก IP ตามนโยบายแอป เลข nonce ถูกเก็บเป็น hash และใช้ป้องกันการสร้างใบงานซ้ำเมื่อกดส่งซ้ำ ใช้ REMOTE_ADDR โดยตรง ไม่เชื่อ X-Forwarded-For ที่ client ส่งเอง หากติดตั้งหลัง reverse proxy ต้องตั้ง trusted proxy ที่ web server ให้ถูกต้อง

## ติดตั้ง

รัน `php scripts/migrate.php --no-create-db` ก่อนใช้โค้ดใหม่ เพื่อเพิ่ม migration `008_public_repairs.sql` สำหรับฐานทดสอบใช้ `--test` เพิ่มด้วย ข้อมูลเดิมไม่ถูกล้าง

ใน preview ฐานทดสอบจะเห็นแถบ “พื้นที่สาธิต” และใบงานใหม่มี is_demo=1 ลิงก์ `127.0.0.1` ใช้บนเครื่องนี้เท่านั้น เมื่อนำขึ้นโดเมนที่ใช้งานจริงจึงแชร์ลิงก์หรือทำ QR ให้ลูกค้าสแกนจากโทรศัพท์ได้
